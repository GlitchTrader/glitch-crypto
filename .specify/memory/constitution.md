# Glitch Crypto Constitution

## I. Native truth before inference

The selected venue is authoritative for account, balance, position, order, fill, margin, liquidation, and native protection state. Raw venue evidence is retained before normalization. Missing, delayed, contradictory, or unreconciled state is uncertainty, never invented fact.

## II. Probabilistic cognition; deterministic execution

Numerical models and Hermes may estimate and judge opportunity, direction, timing, geometry, and management. Only deterministic code may authenticate, bind identity, calculate venue-valid quantities, enforce hard policy, persist mutation intent, submit orders, reconcile outcomes, and journal evidence.

## III. Protection is part of entry

A filled quantity is not accepted as safely open until exact native stop and intended target ownership are proven. Partial fills and reductions preserve or rebuild exact protection for the surviving quantity. If protection cannot be proven, the only permissible fallback is explicit reconciliation or reduce-only emergency flatten.

## IV. Ambiguity is a state

Timeout, disconnect, missing callback, or elapsed time does not prove an order failed. Every mutation uses durable UUID/body identity and an evidence-before-mutation outbox. Unknown outcomes remain nonterminal and cannot be blindly resubmitted.

## V. Survival-adjusted objective

The default daily protected-profit objective is 0.5% of the UTC day's starting usable pot. The objective is configurable and may activate a protected-equity floor. It never creates a setup, determines trade geometry, forces activity, or grants a loss allowance. Liquidation is never a stop.

## VI. Attributable, reversible evolution

Market/model learning, decision/metacognitive learning, and portfolio/management learning are separate evidence lanes. A lesson or model gains production influence only through versioned, attributable, contradiction-aware promotion with an evaluation metric and rollback. A single outcome cannot create a rule. Infrastructure defects never become market memory.

## VII. Evidence-gated promotion

Implementation, deterministic tests, replay, shadow runtime evidence, canary mutation, and production acceptance are distinct states. No stage implies profitability or readiness for the next stage. Real venue capabilities are accepted only from official contracts plus observed sanitized runtime evidence.

## VIII. Minimal single-writer architecture

Begin with one process, one active execution signer, one account, one venue, one instrument, and one open-position scope. Add distribution, concurrency, instruments, and venues only when measured need and acceptance evidence justify the added failure modes.

## Governance

This constitution outranks plans, prompts, skills, memory, and implementation convenience. Changes require an ADR, updated acceptance tests, and a rail item. Safety-reducing changes require explicit human approval. Profitability is empirical and never constitutional fact.
